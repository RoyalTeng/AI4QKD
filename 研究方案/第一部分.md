## 2. QKD协议的统一表示 (Protocol DSL 3.0: 量子-经典图流 QCGF)

### 2.1 QCGF DSL的设计哲学
QCGF DSL的设计遵循以下核心哲学：
1. **原子性（Atomicity）**：协议分解为最小操作单元。
2. **模块化（Modularity）**：操作被定义为独立节点类型。
3. **图结构（Graph Structure）**：协议依赖关系用有向边表示。
4. **参数化（Parameterization）**：所有物理/逻辑参数明确定义。
5. **参与者归属（Party Attribution）**：标记操作执行方。

### 2.2 节点类型 (Node Types)
包括：
- **量子源 (QSP)**：光子态制备，支持单光子、WCP、纠缠态等。
- **量子操作 (QOP)**：酉变换或噪声操作，如 Hadamard、CNOT、PhotonLoss。
- **量子信道 (QC)**：Fiber、FreeSpace。
- **量子干涉 (QI)**：分束器、干涉仪。
- **量子测量 (QM)**：投影测量、POVM、贝尔态测量。
- **经典信息源 (CIS)**：随机数发生器、哈希函数。
- **经典逻辑操作 (CLO)**：逻辑门、纠错、哈希、奇偶校验。
- **经典信道 (CC)**：公共信道、安全信道。
- **经典决策 (CD)**：IfElse、Loop、Switch。
- **密钥提取 (KE)**：协议的最终输出。

### 2.3 边类型 (Edge Types)
- **QF**：量子流  
- **CF**：经典流  
- **ControlF**：控制流  
- **QCIF**：量子-经典接口流  

### 2.4 参与者建模
节点和边均标注参与者（Alice, Bob, Eve, Charlie）。

### 2.5 DSL的抽象表示与存储
- 协议用有向无环图（DAG）存储。
- 使用 Python `networkx` 实现。

## 5. QCGF DSL设计思路深度分析

### 5.1 设计哲学的核心理解

基于对研究方案的深入分析，QCGF DSL的设计体现了以下关键思想：

#### 🎯 节点 = 原子操作单元
节点代表QKD协议中的**最小可执行或可描述的操作单位**，每个节点都有具体的物理或逻辑功能：

**量子操作节点示例**：
```python
# QSP (量子源) - 量子态制备操作
QSP_params = {
    "intensity": 0.1,           # 平均光子数 μ (WCP)
    "polarization": "H",        # 初始偏振方向
    "phase": 0.0,              # 初始相位
    "wavelength": 1550e-9,     # 光子波长
    "coherence_time": 1e-9,    # 光源相干时间
}

# QC (量子信道) - 量子传输操作
QC_params = {
    "length": 50.0,                    # 信道长度 (km)
    "loss_per_unit": 0.2,             # 每单位长度损耗 (dB/km)
    "depolarization_rate": 0.01,      # 传输中的去极化率
    "dephasing_rate": 0.01,           # 传输中的相位退相干率
    "channel_type": "fiber",          # 信道类型
    "background_photon_rate": 1e-6,   # 背景光子噪声率
}

# QM (量子测量) - 量子测量操作
QM_params = {
    "detector_efficiency": 0.8,        # 探测器量子效率
    "dark_count_rate": 1e-6,          # 暗计数率
    "dead_time": 1e-6,                # 探测器死时间
    "afterpulse_probability": 0.01,   # 余脉冲概率
}
```

#### 🔗 边 = 信息流约束
边表示**不同类型信息流的连接约束**，定义什么类型的信息可以在节点间流动：

```python
# 量子流 (QF) - 量子信息流约束
QF_constraints = {
    "flow_type": "quantum_information",
    "allowed_connections": ["QSP→QC", "QC→QM", "QSP→QOP", "QOP→QM", "QI→QM"],
    "prohibited_cycles": True,  # 维持DAG结构
}

# 经典流 (CF) - 经典信息流约束  
CF_constraints = {
    "flow_type": "classical_information",
    "allowed_connections": ["CIS→CLO", "CLO→CC", "CC→CD", "QM→CLO", "CLO→KE"],
    "data_types": ["measurement_results", "key_material", "control_signals"],
}

# 量子-经典接口流 (QCIF) - 特殊混合流
QCIF_constraints = {
    "flow_type": "quantum_classical_interface",
    "allowed_connections": ["QM→CLO", "QM→CD"],
    "conversion": "quantum_measurement → classical_bits",
}
```

### 5.2 当前实现的问题诊断

#### ❌ 参数归属混淆问题

**问题表现**：
```python
# 当前实现中的重复定义
NodeType.QC: {
    "loss": 0.1,              # 量子信道节点的损耗参数
    "distance": 50.0,         # 量子信道节点的距离参数
    "noise": 0.01,            # 量子信道节点的噪声参数
}

EdgeType.QUANTUM: {
    "loss": 0.1,              # 边也定义了相同的损耗参数！
    "distance": 50.0,         # 边也定义了相同的距离参数！  
    "noise": 0.01,            # 边也定义了相同的噪声参数！
}
```

**问题分析**：
1. **参数重复定义**：同一个物理概念在节点和边中都有定义
2. **职责混淆**：边承载了本应属于操作节点的物理参数
3. **语义不清**：不清楚哪个参数是"权威"值
4. **计算风险**：可能导致损耗等参数的重复应用

### 5.3 正确的设计模式

#### ✅ 节点专注操作参数，边专注连接约束

**节点参数设计**：
```python
# 量子信道节点 - 承载所有传输操作的物理参数
NodeType.QC: {
    # 基本传输参数
    "length": 50.0,                    # 信道长度 (km)
    "loss_per_unit": 0.2,             # 损耗系数 (dB/km)
    "channel_type": "optical_fiber",   # 物理介质类型
    
    # 物理特性参数
    "attenuation": 0.2,               # 衰减系数 (dB/km)
    "dispersion": 17.0,               # 色散系数 (ps/nm/km)
    "core_diameter": 9.0,             # 纤芯直径 (μm)
    "numerical_aperture": 0.12,       # 数值孔径
    
    # 噪声特性参数
    "depolarization_rate": 0.01,      # 去极化率
    "dephasing_rate": 0.01,           # 相位退相干率
    "background_photon_rate": 1e-6,   # 背景光子噪声率
    
    # 环境参数
    "temperature": 20.0,              # 环境温度 (°C)
    "humidity": 50.0,                 # 相对湿度 (%)
    "vibration_level": "low",         # 振动水平
    
    # 量子特性
    "coherence_time": 1e-9,           # 相干时间 (s)
    "decoherence_rate": 1e6,          # 退相干率 (1/s)
    "entanglement_fidelity": 0.9,     # 纠缠保真度
}
```

**边约束设计**：
```python
# 量子流边 - 只定义连接规则和流量约束
EdgeType.QUANTUM: {
    # 连接约束
    "allowed_source_types": ["QSP", "QOP", "QC", "QI"],
    "allowed_target_types": ["QOP", "QC", "QI", "QM"],
    "forbidden_cycles": True,
    
    # 流量约束（如果需要）
    "max_photon_rate": 1e6,           # 最大光子传输率 (photons/sec)
    "allowed_quantum_states": ["single_photon", "coherent", "entangled"],
    
    # 兼容性检查
    "wavelength_matching": True,       # 是否需要波长匹配
    "polarization_preserved": True,    # 是否保持偏振
}

# 经典流边 - 只定义信息流约束
EdgeType.CLASSICAL: {
    # 连接约束
    "allowed_source_types": ["CIS", "CLO", "QM", "CD"],
    "allowed_target_types": ["CLO", "CC", "CD", "KE"],
    
    # 数据类型约束
    "supported_data_types": [
        "measurement_results",         # 测量结果
        "raw_key_material",           # 原始密钥材料
        "sifted_key",                 # 筛选后密钥
        "error_corrected_key",        # 纠错后密钥
        "control_signals",            # 控制信号
        "authentication_data",        # 认证数据
    ],
    
    # 带宽约束（如果需要）
    "max_bit_rate": 1e9,              # 最大比特率 (bits/sec)
    "error_correction_overhead": 1.2,  # 纠错开销系数
}
```

### 5.4 BB84协议的正确DSL表示

#### 完整的协议图结构：
```
Alice端：
  QSP(WCP, μ=0.1) → [QF] → QC(Fiber, 50km, 0.2dB/km) → [QF] → Bob端QM

Bob端：  
  QM(ProjectiveMeasurement, η=0.8) → [QCIF] → CLO(基比对)
  
经典后处理：
  CLO(基比对) → [CF] → CLO(筛选) → [CF] → CLO(QBER估算) → [CF] → CD(决策)
  CD(决策) → [ControlF] → CLO(纠错) → [CF] → CLO(保密放大) → [CF] → KE(密钥输出)
```

**关键设计要点**：
1. **物理参数**都归属于相应的操作节点
2. **连接约束**由边的类型来强制执行
3. **信息流**类型明确，避免不兼容的连接
4. **控制流**用于实现协议的条件执行逻辑

### 5.5 设计原则总结

#### 🔧 节点设计原则：
1. **单一职责**：每个节点只负责一种原子操作
2. **参数完整**：包含该操作所需的所有物理/逻辑参数
3. **状态封装**：节点内部状态独立，通过边进行信息交换  
4. **可组合性**：节点可以灵活组合形成复杂协议

#### 🔗 边设计原则：
1. **纯连接语义**：只表示信息流的类型和方向
2. **类型安全**：严格的连接约束，防止不兼容的连接
3. **无状态**：边本身不保存状态，只是信息传递通道
4. **语义清晰**：明确的信息流类型定义

#### 🎪 整体设计原则：
1. **层次分明**：量子层、经典层、控制层职责清晰
2. **参数归属明确**：物理参数归节点，约束规则归边
3. **AI友好**：结构化表示便于GNN学习和处理
4. **可验证性**：支持形式化验证和安全分析
